# 37 — the rom-claim backing gate

> Status: LIVE — what `make rom-unbacked` proves, the `backed_by` hatch, and the five stated limits (three now closed)

*Closes the presence-side hole in `claims.rom`: a claim the allocator packs but
no `.incbin` fills. This doc describes the gate **as it now is** — read §3 and
§5 as the contract and treat anything that contradicts them as a bug in one or
the other.*

---

## 1. The bug, and the asymmetry behind it

`rgb_gradient`'s `grad_tabs` `rom` claim was generated by its asset tool,
correctly prerequisited in the Makefile, and packed by the allocator — **and
never `.incbin`'d by any asm file.** The ROM contained no gradient table at that
address. Three HDMA channels streamed whatever bytes happened to live there as
`COLDATA`. The only visible symptom was a missing backdrop wash, and **every
gate stayed green**: `make register`, `no_literals`, `make width-check`, the
allocator's own packing, and the full pytest suite.

The asymmetry that allowed it:

| direction | question | checked by | verdict before this gate |
|---|---|---|---|
| **drift** | does this claim still sit where its data sits? | `.assert ^label = ES_R_<NAME>_BANK` at each claim site | asserted hard, at assembly time |
| **presence** | does this claim have *any* data? | — | **not asked anywhere** |

The information needed for the second question is the same information the
first one already carries: the claim site's tie to the emitted `ES_R_*` symbol.
The gate reads exactly that tie and asks whether it exists.

Note what makes this class nastier than a plain missing file. The `.assert`s
still pass with the `.incbin` gone: the label lands at the claim's address
either way, because the allocator's packing did not change. **ca65 itself
accepts the broken file.** Nothing short of a presence check can see it.

---

## 2. Where it lives, and why

`allocator/no_literals.py`, as a pass `scan_rom_backing`, wired into `main()`
after the per-file loop.

- It already receives `--map <symbol_map.json>` — **the composition being
  built**, with every `rom` placement in it.
- It already receives the full list of hand-authored `.asm` files for that
  composition.
- It is already the build-refusal surface for "the tree disagrees with the
  map", which is precisely what an unbacked claim is.

The pass is **whole-invocation**, not per-file: "is this claim backed anywhere
in the composition" is a question no single file can answer. Findings are
reported against the symbol map path with line 0, because the tree's fault here
is an *absence*, and an absence has no line number.

---

## 3. The semantics

> **A `rom` placement is BACKED when either**
>
> **(a)** one of the files **in this composition's translation unit** holds an
> `.incbin` whose **declaration block** references one of that placement's
> emitted symbols
> (`ES_R_<SYM>_{BANK,ADDR,OFF,SIZE}`, or the bare `ES_R_<SYM>`) — literally, or
> through a ca65 `.sprintf` template that expands to it; **or**
>
> **(b)** its `[[claims.rom]]` declares `backed_by = "<statement>"`, a non-empty
> prose statement naming the compilation unit outside the `no_literals` scope
> that supplies the bytes.
>
> **Otherwise it is a build refusal** naming the claim, its feature, its scope,
> its size, its emitted symbols, and both ways to fix it.

**The translation unit** is the `.include` closure of the root `.asm` — the
first positional file, or `--asm-root`. This is not a detail: **scanned is not
assembled**, and reading the two as the same thing was the gate's own bug one
level up. Three hand-maintained lists decide membership, and the gate used to
read the loosest:

| list | who reads it | microzero |
|---|---|---|
| `game.toml` `globals` + `[[scene]].features` | the **allocator** — what gets packed | 12 globals + 3 scenes |
| `main.asm`'s `.include` closure | **ca65** — what gets bytes | 19 `.asm` |
| the Makefile's `$(wildcard engine/features/*/*.asm)` | the **gate** | 28 files |

Nine of the engine `.asm` files the Makefile hands the gate for microzero are
never `.include`d into it (`breaker_bg`, `breaker_obj`, `input2`, `room_bg`,
`room_hero`, `room_logic`, `save`, `tad_wrapper`, `window_iris`). A claim site
placed in one of those credited the claim while contributing **no bytes to the
ROM** — the original `grad_tabs` bug, green, one file-move away, and reachable
through the Makefile's own wildcard.

Resolution is by **basename** against the scanned list, because
`.include "scene_mgr.asm"` is resolved by ca65 against a `-I` set this tool
never receives. Generous where it is uncertain (two scanned files sharing a
basename both count), exact where it matters: *a file no `.include` names is
out*. The direction of error is the safe one — a wrong root collapses the
closure and every claim reads UNBACKED, loudly.

The reach is **printed** — state the limit *and* say how far the check got:

```
rom backing: 24 claim(s) (24 via an .incbin claim site, 0 via a declared
backed_by; credited from 19/28 scanned file(s) — the rest are not in this
composition's .include closure)
```

**The declaration block** runs from the nearest preceding label definition
through the directives that follow the `.incbin`, stopping at the next label,
`.segment`, or `.incbin`. That is exactly the shape every claim site in the tree
already has:

```asm
grad_tabs_bin:                                   ; <- block starts here
    .incbin "brk_grad.bin"
.assert ^grad_tabs_bin = ES_R_GRAD_TABS_BANK, error, "..."
.assert .loword(grad_tabs_bin) = ES_R_GRAD_TABS_ADDR, error, "..."
sky_chr_bin:                                     ; <- and ends here
```

**The narrowness is the teeth, not fussiness.** A wide line-radius window would
let a *neighbouring* blob's `.assert`s credit the claim whose own `.incbin` is
the missing one — which is the exact failure being closed. Measured: with
`grad_tabs_bin:` and both its `.assert`s left in place and only the `.incbin`
deleted (the variant ca65 accepts), the gate still refuses.

The cost is that a claim-site shape whose `.assert`s are **separated from the
`.incbin` by another label** is refused rather than accepted. That is loud, with
a message naming the required shape, and it is the correct direction of error
for a gate.

`.assert`s placed *before* the `.incbin` are **accepted**, and deliberately so:
the block is bounded by the label, and everything between that label and the
next boundary is the same claim site whichever side of the `.incbin` it sits on.
(This paragraph used to say they were refused. Measurement said otherwise — the
rule was right, the sentence was not. Pinned now by
`test_asserts_before_the_incbin_are_accepted`.)

A label on the **same line** as the `.incbin` (`font_bin: .incbin "x.bin"`) is
read too, and its block starts at that line rather than walking backwards into
the preceding blob. The bare `^\s*\.incbin` anchor missed the shape entirely —
claim reported unbacked, with a refusal telling the author to add the label,
`.incbin` and `.assert` they already had. The vendored TAD generator emits
exactly it (`assets/audio/export/tad_audio_data.asm:119`), so this was a live
false negative waiting for the first generated unit brought inside the scope.

### Boundary cases, and how each is handled

**1 · Bytes supplied by a vendored or generated unit outside the scope.**
`tad_rom`'s `tad_export` is the live case: 32 KB whose bytes come from
`assets/audio/export/tad_audio_data.asm` — a *separate* ca65 compilation unit
(`$(BUILD)/rm_tad_data.o`, `$(BUILD)/bk_tad_data.o`), deliberately outside the
`no_literals` scope — and whose claim site is a **linker segment**
(`AUDIO_DATA0` → ROM1) rather than an `ES_R_*` assert. It is legitimately
backed; the default rule cannot see it.

Handled by **`backed_by`**, an optional field on `[[claims.rom]]`. It is a
*declaration*, in the repo's own idiom — "a judgement someone made becomes a
declaration the build proves". Two bars, both enforced in `schemas.py` where the
claim is parsed, both `SchemaError` rather than warning:

1. **Non-empty.** The `; REG-LINT: ok — <reason>` / `; WIDTH-LINT: ok —
   <reason>` convention this repo already runs on: an escape hatch that need not
   say why is a quiet way to turn the rule off.
2. **It must CITE — at least one repo-relative path in the string has to exist
   on disk.** Non-emptiness alone was the whole bar when this landed, and that
   is weaker than the hatch's blast radius. The lint-override precedent differs
   on both axes that matter: a `WIDTH-LINT` override suppresses *one finding at
   one site*, and it lives in the `.asm` line the reviewer is already reading.
   `backed_by` suppresses *a claim's entire presence check* — every chunk of a
   `bank_tiled` one — from a `feature.toml` the reviewer of an ASM change never
   opens. So `backed_by = "the asset tool generates it"` would have re-opened
   the `grad_tabs` bug in one line, with a plausible sentence and nothing to
   check it against. It is now refused; `tad_export`'s statement passes
   unchanged.

   Deliberately no stronger than a citation check. The string is prose for a
   human, and nothing short of reading the linker's output could prove the
   cited unit really supplies the bytes. What this buys is *falsifiability*:
   the sentence names something a reviewer can open.

The declaration is carried on `Placement` into `symbol_map.json` (rom
placements only — a `backed_by` key on 40 non-rom placements reads like a field
someone forgot to fill), so the gate reads the map rather than re-opening
`feature.toml`.

**2 · `bank_tiled` claims.** The allocator emits one placement per bank window
(`ES_R_WORLD_MAP_T0` … `_T7`), and the only claim site anyone can write is a
`.repeat` whose chunk symbols exist *only* inside `.sprintf` templates and
nowhere as text. Handled by template expansion: a reference containing a
conversion spec compiles to a regex (`%d`/`%i`/`%o`/`%u`/`%x`/`%X` → `\d+`,
`%s` → `\w+`) matched against the emitted symbols. 12 chunk placements in the
live tree depend on this.

> Implementation note worth keeping: the reference must be split on the
> **original** text and only the literal parts upper-cased. Upper-casing first
> turns `%d` into `%D`, the spec pattern stops matching, every template
> compiles to a literal regex that matches nothing, and the whole tree reads as
> unbacked. That was a real intermediate state.

**3 · Claims deliberately reserved with no data yet.** **None exist in the
tree** — all compositions' claims are backed by a claim site, except the one
`tad_export` case above. Should one ever be wanted, `backed_by` is the honest
place to say so (`backed_by = "reserved; nothing writes it yet — <why>"`),
because it forces the reservation to be *stated* rather than to look identical
to the bug.

**4 · A caller with a PARTIAL file list.** The pass is the only
whole-composition check in `no_literals`, and a subset of a composition's ASM
cannot answer it — the reg-gate plant tests hand one planted file a whole
game's map, and all 24 claims read as unbacked. Handled by
**`--partial-files`**, an **opt-OUT**: the six Makefile invocations that gate
real ROMs pass complete file sets and get the check by *default*, and a partial
caller must say it is partial. An opt-in flag would have been silent everywhere
it was forgotten, which is the failure mode being closed. The summary line then
reports `rom backing: SKIPPED`, never "clean" — a silent skip prints a verdict
about a check that never ran. Pinned by
`test_partial_files_skips_and_SAYS_it_skipped`, which also asserts the same
invocation *without* the flag is refused, so the arm cannot pass for another
reason.

**5 · Per-game, not tree-wide.** The check runs against `--map`, which is
exactly the composition being built. A claim in a feature no game composes has
no placement, reserves no bytes, and can back nothing — there is nothing to
check and nothing at risk. Tree-wide would have to invent a composition to
check against and would report on features that are in no ROM.

## 4. What the fixture proves

`tests/fixtures/rom_backing/` — one game, three claims, **two mains over one
allocation** so the only variable is the one the gate reads:

| claim | shape | `main_backed.asm` | `main_unbacked.asm` |
|---|---|---|---|
| `fixture_blob` | plain, literal `.assert` | claim site present | **removed → must be reported** |
| `fixture_tiles` | `bank_tiled` → `_T0`/`_T1`, `.repeat` + `.sprintf` | claim site present | **removed → both chunks must be reported** |
| `fixture_extern` | `backed_by` declared | *no* claim site | *no* claim site — **must NOT be reported on either arm** |

`make rom-unbacked` runs the allocator once, then the gate twice, and requires:

1. the **control** arm exits 0 — *a gate that refuses everything is not a gate*;
2. the **violation** arm exits non-zero;
3. …with `ROM CLAIM UNBACKED` — not some other failure;
4. …naming `ES_R_FIXTURE_BLOB` (the plain case);
5. …naming `ES_R_FIXTURE_TILES_T0` (the templated case);
6. …and **not** naming `ES_R_FIXTURE_EXTERN` — the hatch must not be swept up
   with the findings around it, which is the one way this gate could make the
   tree worse than no gate.

**Polarity follows `toy-bad`, for `toy-bad`'s reason**: success means *the gate
refused*. The target is not itself inverted. A consumer nobody updates then
fails **loud** on a healthy repo rather than passing a toothless check in
silence.

### The teeth, measured

`tests/test_rom_backing_gate.py` (40 tests) carries the pair that separates a
verdict from a constant, on `tests/test_make_gates.py`'s discipline:

- `test_target_passes_on_the_real_fixture` — fails a refuse-everything gate;
- `test_target_goes_RED_when_the_rule_is_removed` — **THE plant**: replaces the
  `scan_rom_backing(...)` call in `allocator/no_literals.py` with `pass`, runs
  `make rom-unbacked`, and requires non-zero + `no teeth`. Restored in a
  `finally`; the module holds `repo_tree_lock`.

Neither alone distinguishes a constant from a verdict. Together they force the
exit status to be a function of the tree.

Plus: the narrowness case (only the `.incbin` deleted — the variant ca65
accepts), the template-expansion unit test, the `backed_by`-on-both-arms test,
the empty-`backed_by` schema refusal, the map-plumbing test, and an in-tree
guard that regenerates each shipping game's map into `tmp_path` (so it cannot
pass by reading a stale build map) and runs the gate over the Makefile's file
set.

**The teeth that had to be added later.** The plant catches *removal*; the
narrowness test catches every line-radius weakening of ≥6 lines. Two mutations
passed all 13 of the original tests — a **±3-line radius** and **substring**
literal matching — and ±3 is not a strawman: it is the radius
`; WIDTH-LINT: ok` and `; CHANNEL-LINT: ok` use, and `game/breaker/main.asm`
spaces its claim sites **4** lines apart, so the rule was demonstrably blind on
the shipping tree while the fixture (~6 lines apart) said otherwise. Both
mutations are now red:

- `test_the_rule_holds_at_the_REAL_trees_claim_site_spacing` runs the rule over
  the real `game/breaker/main.asm` with one `.incbin` deleted, and requires the
  neighbour 4 lines below not to credit it — with a positive control so it
  cannot pass by the rule crediting nothing;
- `test_a_literal_reference_matches_EXACTLY_not_as_a_substring` pins
  `ES_R_AB` / `ES_R_A` / `ES_R_ABCD` / `ES_R_ABC_EXTRA` against `ES_R_ABC`'s
  claim site.

Every fix carries a test verified to fail without it — each was re-run against
the reverted rule.

## 5. KNOWN LIMITS

Stated rather than papered over — which means stating the limit **and**
printing how far the check got (see "The limits' reach, printed", below). They
are also in the passes' comment blocks in `allocator/no_literals.py`, where an
implementer will hit them.

Three of the five were closed and are kept here, struck through, with what was
measured: a limit that turns out to be closable is worth recording as such, and
limit 1's history is the reason this section carries measurements rather than
reasoning.

1. ~~**`.repeat` counts are not evaluated.**~~ **CLOSED.** A templated reference
   still credits every chunk of the claim whose name it matches — a textual scan
   cannot evaluate ca65 arithmetic — so a `.repeat 2` wrapping a 4-chunk claim
   *would* read as backing all four. The limit was closed by removing the number
   instead of evaluating it.

   The original text said the residue was caught by "the linker's segment sizes
   and the per-chunk `.assert`". **That was measured and it is false.** Changing
   `game/microzero/main.asm`'s `.repeat 8, WI` to `.repeat 7, WI`:

   | check | result |
   |---|---|
   | the rom-backing gate | green — 24 claims, 24 via a claim site |
   | `ca65` (the Makefile's exact flags) | exit 0 |
   | `ld65 -C vendor/rom/lorom_512k.cfg` | exit 0 |
   | ROM size | 524,288 B — identical |
   | bytes differing from a good build | **18,478**, first at `0x007FDC`, `$FF` fill |

   An unused ca65 equate is not a diagnostic, and `lorom_512k.cfg` marks the
   BANK segments `optional = yes`, so a short segment is not a link error
   either. Nothing caught it. A stated-and-wrong backstop is worse than a
   stated hole: it retires the question.

   **The close.** The allocator emits `ES_R_<NAME>_CHUNKS = N` beside the
   per-chunk symbols, and the claim site takes it:

   ```asm
   .repeat ES_R_WORLD_MAP_CHUNKS, WI     ; not `.repeat 8`
   ```

   A hand-written count around a templated claim site is now a **build
   refusal** (`NARRATED CHUNK COUNT`, `scan_chunk_count_narration` in
   `allocator/no_literals.py`), naming the symbol to use instead. That pass is
   per-**file** and is *not* skipped by `--partial-files`: unlike "is this claim
   backed anywhere", "is this count narrated" is answerable from one file.

   Converted with it: `mode7_stream.asm`'s per-chunk MVN stub table, which
   narrated the same 8 one step downstream of the claim site. Inside a `.scope`
   the reference needs the global-scope operator (`::ES_R_WORLD_MAP_CHUNKS`) —
   without it ca65 reads the name as a scope-local forward reference and says
   `Constant expression expected`.

   Residue after the close: a claim site could still narrate a count in a form
   the scanner does not read as a literal (`.repeat 4+4`, or a hand-written
   equate). That is a much narrower shape than a bare number, and it fails in
   the same safe direction the moment anyone writes the obvious thing.

2. **The bytes are not inspected.** This proves an `.incbin` exists and is tied
   to the claim. It does not prove the file it names holds the right bytes, is
   non-empty, or is the size the claim declared. ca65 would need to export the
   included size for that. (A `SIZE` cross-check is a plausible follow-up: emit
   the claim size, `.assert` the included extent. It is separate work.)

3. **`.include`d files are not READ for claim sites** — the single-file limit
   every other pass in `no_literals` carries. A claim site inside an `.inc` not
   itself in the scanned list is invisible. (The `.include` graph *is* now
   parsed, but only to decide which of the **scanned** files are in the
   translation unit — see §3. Nothing outside the argument list is opened.)
   Every claim site in this tree is in a scanned `.asm`; a future one that is
   not fails **loud** (refused, with `backed_by` named in the message), never
   silently.

4. **Conditional assembly is not evaluated**, so a claim site inside an `.if` /
   `.ifdef` / `.ifndef` / `.ifblank` / `.ifconst` **does not credit its claim**.
   Measured before the close: `.if 0` around a whole claim site,
   `.ifdef NEVER_DEFINED` around it, and — the shape §1 calls the nasty one —
   `.if 0` around *only* the `.incbin` with the asserts left outside all
   credited the claim while ca65 emitted nothing.

   Closed in the safe direction rather than by teaching the scanner ca65
   conditionals: an unevaluable claim site is skipped, the claim reads
   UNBACKED, and the author either makes it unconditional or declares
   `backed_by`. The skipped count is on the summary line —
   *`[N .incbin(s) inside an unevaluated .if/.ifdef did NOT credit — KNOWN
   LIMIT 4]`* — so the residue is a number rather than a sentence in this doc.

   `.repeat` is deliberately **not** treated as a conditional: a `.repeat` with
   a derived count is the blessed claim-site shape, and a narrated one is
   already refused by limit 1's pass.

5. **`%s` in a claim-site template is refused, not expanded.**
   Template expansion exists for chunk *indices*: `%d` compiles to `\d+`. `%s`
   is a name *fragment* and compiled to `\w+`, so `.sprintf("ES_R_%s_BANK",
   NAME)` became `^ES_R_\w+_BANK$` — matching **every** rom symbol in the
   composition. One such claim site anywhere in the translation unit would have
   turned the presence check off for the whole ROM while the census still read
   `N via an .incbin claim site`, indistinguishable from clean. Nothing in the
   tree uses it (all 8 templates are `%d`), and a name fragment is not a chunk
   index, so it is a build refusal (`BLANKET ROM TEMPLATE`).

Not a limit but worth stating: the gate says nothing about whether anything
*reads* the claim. An unread blob is waste, not corruption, and the allocation
report already shows the bytes.

### The limits' reach, printed

State the limit **and** print how far the check actually got — this gate did
only the first at the start. Now the summary line carries a reach number for
each limit that has one:

| limit | reach on the line |
|---|---|
| 3 (scanned vs assembled, §3) | `credited from 19/28 scanned file(s)` |
| 4 (conditionals) | `[N .incbin(s) inside an unevaluated .if/.ifdef did NOT credit]`, printed only when non-zero |
| 1, 5 | no residue to count — both are build refusals now |
| 2 (bytes not inspected) | no number is possible without ca65 exporting the included size |

## 7. A test whose name was a contract its assertion did not meet

Worth recording in full, because the first diagnosis of it was wrong and the
wrong diagnosis was plausible.

`test_the_conditional_residue_is_reported_in_the_census` was unpinned: deleting
the census suffix from `summarise()` left the **whole suite green**.

The first explanation was that the refusal the test observes fires for the
closure reason (`19 of 28 scanned file(s) are reachable`) rather than the
conditional one — but that closure sentence is **boilerplate in every
`ROM CLAIM UNBACKED` message** (`no_literals.py`'s finding text), so its
presence says nothing about which reason fired.

What actually happens: **`summarise()` is only reached on the GREEN path.**
`main()` prints `NO-LITERALS FAILED` to stderr and `return 1`s two lines above
its `print(summarise(...))`. The test wrapped microzero's *only* `font_bin`
claim site in a never-taken `.ifdef`, which makes that claim unbacked and the
run red — so the census line the test is named for **was never in the output it
read**. The conditional skip *is* exercised (`in_conditional` == 1); it simply
has nowhere to print. The assertion therefore fell back to observing the
refusal, which a sibling unit test already covers.

The close:

- the plant is now a **duplicate** never-taken claim site for a claim its real
  site already credits, so the run stays green and the residue lands on a line
  that is actually printed;
- a **control arm** asserts the unmodified tree prints the census *without* the
  suffix, so the assertion cannot pass against an unconditional suffix;
- the refusal behaviour the old assertion really tested is split out as
  `test_a_conditional_claim_site_is_REFUSED`, which is what it was doing.

Re-measured: planting `if rom.get("in_conditional")` → `if False` now turns the
test **red**, where before 762 tests passed and nothing caught it.

### Still open: the census is suppressed exactly where it would help most

Not a correctness hole, and recorded so it is a stated gap rather than a
discovered one:

Because `summarise()` runs only on success, an author who wraps a claim site in
`.ifdef DEBUG` gets `ROM CLAIM UNBACKED: 'ES_R_FOO' … NO .asm IN THIS
COMPOSITION'S TRANSLATION UNIT includes its bytes`, looks at `main.asm`, sees
the `.incbin` sitting right there, and has **no hint**. The one line that
explains it — `N .incbin(s) inside an unevaluated .if/.ifdef did NOT credit` —
is on the path they are not on. The fix is ~5 lines (emit the residue note
alongside the refusal) and is testable by the same control/plant pair used
above.

### The gate's first contact with a rail it had never seen

The gate was developed against a handful of compositions; `platformer` and
`shmup` landed independently and their `rom` claims had never been evaluated.
Both invoke `no_literals` with complete file lists and no `--partial-files`, so
they are checked **by default**. Both passed on first contact.

Worth recording *why* `platformer` passed: it composes `rgb_gradient`, so it
carries `grad_tabs` — **the exact claim whose unbacked shipment motivated this
gate**. That rail hit the bug independently and fixed it from the symptom, and
the comment it left above the claim site
(`game/platformer/scenes/play.asm:1179-84`) describes that symptom in the
gate's own terms: *"an armed channel reading nothing."* That is the cost of
having held the gate back, legible in the tree.
