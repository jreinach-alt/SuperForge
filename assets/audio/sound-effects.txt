; Demo sound effects — the per-room reverb path (: echo is
; not an IO command; game-triggered echo changes are SFX bytecode).
;
; The two ambience SFX re-shape the shared echo unit to the entering
; room's acoustics using EVOL + EFB only. The echo DELAY is deliberately
; CONSTANT (song header: #EchoLength 128 = #MaxEchoLength) — at the
; vendored pin the compiler structurally refuses set_echo_delay in a
; sound effect (bytecode.rs:3180, BytecodeContext::SoundEffect — an SFX
; cannot know its host song's max_edl), and a constant EDL also removes
; the \edl glitch/settle hazard entirely: the buffer is allocated once at
; song start and never resized. Room character = how much signal feeds
; the 128 ms tail (EVOL) and how long it regenerates (EFB).
;
; The scene fires one of these at enter time, under the transition fade.

=== room_a_ambience ===
    set_echo_feedback   24
    set_echo_volume     12
    rest                4

=== room_b_ambience ===
    set_echo_feedback   96
    set_echo_volume     70
    rest                4

=== footstep ===
    set_instrument_and_gain step F127
    play_note c3 4

; =============================================================================
; The demo SFX vocabulary — the primitives a rail actually needs, shared.
;
; SHARED ON PURPOSE. There is ONE export blob for the whole tree, so a sound
; authored for one rail is linked into all of them. That makes a shared set of
; primitives the architecture working as designed, not a compromise: `laser`
; is the shmup's shot AND the saucer arena's gun, and neither pays for the
; other's.
;
; WHY SO LITTLE NEW SAMPLE DATA. The S-DSP's own noise generator (`play_noise`)
; and pitch sweeps (`portamento_calc`) carry most of this set, so the eleven
; sounds below cost bytecode rather than BRR. Only two new instruments were
; needed — `bell` and `saw`, single-cycle 64-sample loops at ~36 B each —
; because `square_lead` (a 25 % pulse) and `step` (a low-passed footstep burst)
; genuinely cannot voice a bright pickup or a full-spectrum laser.
;
; FLAGS. Defaults are one-channel + interruptible (project file). `both` lets a
; sound occupy either SFX channel so two can overlap; `uninterruptible` is for
; the ones whose loss is a STATE bug rather than a missed noise.
;
; GAIN vs ADSR, AND THE TRAP IN BETWEEN. A percussive one-shot must declare an
; ATTACK. `E<rate>` / `D<rate>` GAIN are DECREASE modes -- they fall from the
; envelope's CURRENT level, and key-on leaves that at zero, so an effect that
; opens `set_instrument_and_gain step E14` decays from silence and is NEVER
; AUDIBLE. It compiles, it queues, it key-ons, and the S-DSP voice reads
; ENVX = 0 forever. Every percussive effect here therefore opens with
; `set_instrument_and_adsr <inst> 15 <decay> <sustain> <rate>` (attack 15 =
; instant); fixed `F<level>` gain is fine as-is, and `I<rate>` (increase) is
; fine because it rises from zero by definition. Caught on the emulator, which
; is the only place it is visible -- CLAUDE.md rule 2.
; =============================================================================

; --- impacts ---------------------------------------------------------------

=== thud ===
    set_instrument_and_adsr step 15 5 0 31

; --- the saucer arena's beam -----------------------------------------------
; These two carry ECHO STATE as well as a sound, which is why they exist at
; all: the arena used to fire `room_b_ambience` / `room_a_ambience` — another
; game's per-room reverb — as its beam cues, so the beam had no sound of its
; own and left the shared echo unit retuned. One SFX does both jobs because
; the ca65 queue only carries ONE sound effect per frame; a separate tone and
; re-shape would contend and the re-shape would win, silently.
; The echo write comes FIRST so the state lands even if the tail is cut.

=== beam_fire === uninterruptible
    set_echo_feedback   96
    set_echo_volume     70
    set_instrument_and_gain saw I18
    play_note c3 sn 2
    portamento_calc c5 keyoff 10 12

=== beam_end === uninterruptible
    set_echo_feedback   24
    set_echo_volume     12
    set_instrument_and_adsr tri_bass 15 4 0 31
    play_note c2 6
